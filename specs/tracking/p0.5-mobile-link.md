# P0.5 — mobile link spike: PASS both targets (2026-07-22)

Contract: `specs/blocks/compiler.md` §3 (Rev 1). Implementation: coding
agent per handoff; reviewed and independently re-verified by the
orchestrator (fresh `out/`, own `cargo test --offline` + `link.sh` runs
on this machine).

## Result

- **Kill criterion: met.** `sh spike/mobile-link/link.sh` with
  `ANDROID_NDK_HOME` set:
  - Android: object + `aarch64-linux-android24-clang` link →
    `ELF 64-bit LSB pie executable, ARM aarch64 … interpreter
    /system/bin/linker64` — PASS.
  - iOS: object + `xcrun --sdk iphoneos clang -target arm64-apple-ios
    -miphoneos-version-min=10.0` link → `Mach-O 64-bit executable arm64`
    — PASS.
  - No binary was executed; no simulator/emulator involved.
- **Consequence: the C-emission fallback is not invoked.** Ship tier
  stays `cranelift-object` AOT. Plan §7's ship-tier-link risk is
  resolved.

## Deliverable

- `spike/mobile-link/` (emitter bin `mobile-link-spike`) +
  `spike/mobile-link/runtime-stub/` (`staticlib`, one C-ABI export
  `subscript_rt_print_i64`). Spike program per contract §3: loop sum
  1..=10, `*3 + 7`, runtime call, return — emitted through
  `cranelift-object` with `is_pic = true`, no TLS.
- Extra link inputs required: none — no `-l`/`-framework` beyond the
  platform defaults for either target; iOS needed only
  `-miphoneos-version-min=10.0` to match the Rust staticlib's minimum OS.
- Host-only unit tests (in the default `cargo test`): both triples'
  objects parsed with the `object` crate — format (ELF/Mach-O), arch
  (Aarch64), `spike_main` defined global, `subscript_rt_print_i64`
  undefined import. Workspace suite green (2 passed).
- Cranelift pin: 0.125.4 (`cranelift-{codegen,frontend,module,object}`),
  `target-lexicon 0.13.5`, exact versions in `Cargo.lock`. Moving the
  pin is a deliberate act per CLAUDE.md. Note for the pin's next move:
  0.126+ requires `serde ≥1.0.228` *(docs — observed at resolution, not
  re-verified here)*, which constrains any future SWC version choice.
- Gap handled at the spike layer: `cranelift-object 0.125.4` does not
  stamp a Mach-O build version for iOS; the emitter sets
  `MachOBuildVersion` (PLATFORM_IOS, minos 10.0) on the `ObjectProduct`
  before emit.

## Environment (measured this run)

Xcode iOS SDK 26.5; Android NDK r30 (`aarch64-linux-android24-clang`);
rustup targets `aarch64-apple-ios`, `aarch64-linux-android`. The NDK
root is supplied via `ANDROID_NDK_HOME` at invocation; it is not
recorded in any committed file.
