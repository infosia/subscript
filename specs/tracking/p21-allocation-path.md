Contract: `specs/blocks/compiler.md` §21, plus `collisions.md` Q29,
which the phase produced rather than started with. Two items done
together because both touch `Context::alloc` and the 16-byte header;
§20.4's rationale — splitting means touching the path twice — applied
unchanged.

## A. Allocator fault injection

`sub_rt_ctx_fail_alloc_after(ctx, n)` refuses the n-th subsequent
allocation. It exists because `TrapKind::AllocationFailure` had six
raise points and **no corpus program could reach any of them**: the
site was represented in the IR and entirely unverified.

**Counts object-level requests, not underlying system allocations.**
The countdown is decremented in `Context::alloc` *before* the tier
dispatch, so a ship-tier chunk allocation cannot be counted on one side
and not the other. This is the only count comparable across tiers —
§18.2d established `live_allocations` is tier-independent while byte
figures are not, so a byte threshold would have given the two tiers
different failure points and could not have been compared at all.

**§21.1 predicted the first run would find allocation-sequence
divergences. It found none.** The prediction rested on P20 having just
removed a C-only per-template allocation. The Phase Review swept 14
accept-corpus programs over **726 injection points** plus 17
hand-written probes — Map, Set, nested templates, `push` inside a
callback, string building in a loop, JSON round-trip, generator frames
including one created in a loop, value-class arrays — and found **zero
divergences** in kind, message, position or pre-fault stdout.

**No continuation through the null payload.** `alloc` returns null on
failure and the check happens after, so generated code holds a null for
a window — the shape P19 found with `ss_scratch`, where a fault was
recorded and 320 bytes were then written into a 256-byte buffer. The
review re-ran AddressSanitizer, verified it was genuinely instrumented
by capturing the compiler invocation through a `$CC` wrapper, and swept
seven trap entries plus twelve probes plus five purpose-built shapes
(a failed allocation immediately indexed, stored into a field, passed
as an argument, interpolated, used as a receiver). Clean.

## B. Per-allocation attribution

The `pos_id` `alloc` already received and discarded is stored in the
header; `sub_rt_ctx_visit_live_allocations` reports
`(class_id, pos_id, payload_bytes)`; the emitted C defines class-id and
position tables a host includes, regenerated byte-identically.

**A variable name was never the alternative.** An allocation is not
bound to a variable — values move between variables and into fields and
arrays — and a leaked allocation is usually reachable from no named
variable at all, which is why it leaked. A loop allocating ten thousand
times has one site and no useful name.

### The header trade, and why it is safe

**§21.2 first claimed the header's fourth word was unused and that
storing `pos_id` was free. It was not.** On the ship tier that word
held each classed block's **exact payload size**, which `collect`'s
mark phase read. The mark phase now traces the **whole size-class
capacity** instead.

The Phase Review attacked the safety claim rather than accepting it: a
classed block reaches the mark phase by exactly two paths — a
never-handed-out bump block from an `alloc_zeroed` chunk, or a
free-list pop re-zeroed across its **full capacity** before the header
is re-armed — and the free-list link is only ever written into blocks
stamped `DEAD_STATE`, which mark skips. Measured: a 200 000-operation
randomized alloc/delete/collect stress filling every request with
`0xF7` and re-scanning `[requested, capacity)` on every live block,
**0 violations**; a resurrection probe (handle at offset 32 of a
40-byte request, freed, reused at 24 bytes, rooted, collected) did
**not** resurrect the victim.

**The cost bound in §21.2 was wrong too**: "at most a factor of two"
holds only for 8-byte-aligned requests. Worst measured word ratio is
**3.0×**, at a 17-byte request — and a 9-byte string hits exactly that
case, since `alloc_str` requests `8 + len`.

## Q29 — produced by the phase, and wrong on its first attempt

Checking whether injection could reach the "not representable" raise
point without new machinery turned up a **compiler panic on a
checker-accepted program**. It could not reach that raise point; it
found this instead.

The first Q29 **did not achieve its own stated purpose.** It set one
limit at `i32::MAX` and bounded a single aggregate rather than the
frame, so `FixedArray<u8, 2147483640>` in a `@CStruct` local still
panicked — and **the value Q29's own text used as its example,
`i32::MAX`, was itself a panicking input.** It also claimed checker
enforcement for closure environments and generator frames when neither
was checked, so the **ship tier accepted programs the dev tier refused
to compile**.

Now two limits: `i32::MAX` for one aggregate, and **2 147 483 632** for
accumulated stack-frame storage, derived from the AArch64 ABI's 16-byte
frame alignment rather than chosen. Seven layout kinds enforced in the
checker.

**The release-build consequence is the part worth remembering.** The
workspace has no `[profile.release]`, so `overflow-checks` is off
there: a release-built compiler would have **wrapped the ABI's negation
instead of panicking, emitting a wrong stack offset silently.** The
debug-build panic was the friendly face of the defect.

The scalar layout table is now **shared** between checker and codegen.
It had been byte-for-byte identical in two crates with no test that
they agreed — and a drift moves the checker's enforced limit off the
backend's real bound, which is exactly how the first Q29 failed.

## Phase Review — 1 CRITICAL, 1 MAJOR, 5 MINOR. All closed.

Both the CRITICAL and the MAJOR were in the Q29 work, not in the
allocation work the phase set out to do. The review verified the
injection knob, the seven trap entries, the attribution visitor and the
generated tables as tier-identical and correct beyond the corpus.

MINORs: the cost bound above; `Map`/`Set` allocation-failure raise
points now have four trap entries; the duplicated scalar table; one
clippy warning in test code.

`cargo build --offline --all-targets` zero warnings; `cargo test
--offline` **578 passed, 0 failed**; `tsc` exit 0; `git diff --check`
clean; clippy at its 16-lib baseline. No pre-existing accept
`.expected` moved. Emitted-C **1.52×** against P20's 1.53×, a valid run

## Carried forward

**The benchmark gate cannot see this phase's only new cost.** No
workload and no `perf-gate` subject calls `collect()`, and the classed
-block `pos_id` store replaces one that was already there, so the
allocation path gained no instruction. The 1.52× figure is a true
statement about the allocation path and says **nothing** about the
mark-phase change. A `collect`-exercising workload would close it —
the same coverage-gap shape P18's review found for array callbacks.
