## 277. The interpreter runs a small matrix witness, not the a22 benchmark

*(Added 2026-11-14.)* Origin: a test cost review of 2026-11-14 at
`8a36c8c1` (item P0, "separate benchmark scale from interpreter
semantics"). Iteration speed is a goal, and a gate's cost is part of
its design (core principle 15).

Problem, measured. In the full gate record of 2026-11-13 at
`8a36c8c1`, `codegen/tests/lir.rs` took 173.57 s in the release step
and 9.03 s in the debug step. The release step sets
`SUBSCRIPT_FULL_INTERPRETER_SWEEP=1`, so the reference interpreter runs
each runnable accept entry, `a22-matrix-propagation` included. A probe
of 2026-11-14 on the release libraries ran the same check, lower, and
interpret path on `a22`: check and lower 0.0019 s, interpret
175.92 s, output equal to the golden. The same program with 64 nodes
and 4 iterations interpreted in 0.0705 s.

`a22` has 10,000 nodes and 100 iterations because it is a benchmark
(`cost: benchmark`). The interpreter observes no semantics at that
scale that it does not observe at a small scale. The dev tier, the
ship tier, and `perf-gate` keep the full-size workload.

### 277.1 Rules

1. `a22-matrix-propagation` carries
   `// interpreter: no — <reason>` (§88 rule 2). The reason states
   that the entry is benchmark-sized, and names the witness of rule 2.
   The entry keeps `cost: benchmark`.
2. A new accept entry `a448-matrix-propagation-witness` is the source
   of `a22` with `NODE_COUNT` 64 and `ITERATION_COUNT` 4. No other
   line differs, except the corpus header. It has no `cost:` line and
   no `interpreter:` line, so the interpreter runs it in both profiles.
3. The dev tier, the ship tier, and the reference interpreter give the
   same bytes for `a448`, and its golden pins them. The golden of `a22`
   does not change. The dev tier and the ship tier still run `a22` on
   each gate.
4. `perf-gate` does not change.
5. A consequence of rule 1: the debug interpreter sweep prints no
   `cost: benchmark` skip line for `a22`. The debug skip count of a
   `full` gate becomes 1 (`perf_gate` only). §88 rule 5 keeps the rule
   for a runnable `cost: benchmark` entry; no such entry remains.
6. No test runs the full-size `a22` in the reference interpreter. The
   witness of rule 2 is the interpreter's observation of this shape.

### 277.2 Acceptance

1. Red first, at the contract commit: the interpreter sweep and
   `compiler/tests/js_corpus.rs` fail on `a448`, because it has no
   golden. (The golden sweep selects only entries with a golden.)
2. The generated corpus index shows `a22` with its `no` reason and
   `a448` with `yes`. The index is regenerated by its generator.
3. `cargo test -p subscript-codegen --test lir --release` with
   `SUBSCRIPT_FULL_INTERPRETER_SWEEP=1` passes. Its wall time, with
   the binary already built, is recorded before and after the change
   in `specs/tracking/test-cost-review-2026-11-14.md`.
4. The full gate passes with `skips 1/0`. No golden other than the new
   `a448` golden moves.

### 277.3 Phase Review

One fresh review. No CRITICAL or MAJOR finding. It found that the
witness keeps each semantic of `a22` that the interpreter observes:
the matrix product, parent propagation, the state across iterations,
the f32 checksum, the LCG, and each of the 17 phases. Three MINOR
findings, each realistic and fixed:

1. §88 rule 5 still gave a debug skip count of 2. It now states 1.
2. The `a22` reason ended with a period, so the index showed `.;`.
   The period is gone, and the generator rewrote the index.
3. The tracking note did not hold the full gate verdict. It now does.
